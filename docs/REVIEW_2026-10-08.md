# Jeopardy application review — October 8, 2026

The application is compact and its ordinary CSV parsing is fast. The highest-value improvements are stricter import validation, reliable recovery and synchronization, and enforcement of scoring rules. Further compression should follow those fixes because the current build changes application text.

This was a review, with no application-source changes. I read the HTML, JavaScript, CSS, build script, and requirements; parsed both demonstration decks; exercised 14 focused parser scenarios; and ran isolated Chrome checks of the source and packaged app. Browser checks blocked external fonts and media. The offline synchronization checks deliberately disabled BroadcastChannel; one also blocked browser storage and delayed board initialization to exercise the advertised fallback. Safari, Firefox, physical projector performance, and a full memory/paint profile were not tested.

**Prioritized findings**

P1 means a correctness or recovery issue worth fixing before the next release. P2 means an important robustness, display, or distribution improvement.

1. **[P1] Invalid decks can report success and produce incorrect scoring values.**

   [CSV transformation](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/app.js:144>) checks four headers but does not require `Value` for grid rounds. It silently skips incomplete rows and unknown rounds, and accepts a deck with no playable clues. [Value conversion](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/app.js:187>) uses `parseInt`: `"1,000"` becomes `1`, `"$1,000"` becomes `NaN`, `"200pts"` becomes `200`, `"200.9"` becomes `200`, a blank becomes `0`, and negative values survive. Negative values reverse normal scoring; non-finite values render incorrectly and become `null` when JSON is saved.

   **Change:** Validate the entire import before committing it. Require finite, positive safe integers for Single/Double clues. Either accept clearly defined money formats or reject them with a row-specific explanation. Report unknown rounds, missing fields, duplicate headers, row-width mismatches, invalid flags, unsupported media types, and multiple Final clues. Show accepted/rejected counts and a preview; never silently discard content. Allow missing rounds only through an explicit supported game format.

2. **[P1] Two distinct clues can share a spent-state key.**

   [Host card rendering](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:896>) and the spectator renderer identify a clue using round, category name, and value. A category containing two $200 clues imports successfully. Skipping the first marks both host cards spent, reproduced in Chrome. Missing or invalid values can create further collisions.

   **Change:** Give each deck, category, and clue its own stable ID. Track spent clues by clue ID. Warn or reject duplicate category/value slots for standard boards; support repeated values deliberately in custom formats. Category wording, punctuation, and value should remain display data.

3. **[P1] HTML-like title and clue text changes the interface instead of displaying literally.**

   [Host titles and previews](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:884>), [spectator category titles](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/board-ui.js:462>), and several team-name/Final screens interpolate input into `innerHTML`. A category containing `<em>` creates an element. A clue reading `Compare <br> and <b>bold</b>` becomes a line break and formatted text in the host preview, although the active clue correctly displays the literal string. Quotes in team names also enter HTML attributes. This can break layouts and permits executable event attributes in imported markup.

   **Change:** Build static structure separately and assign imported names, questions, answers, and input values through `textContent` or `.value`. If formatted clues are desired later, make that a separate constrained format. [MDN recommends textContent for plain user-provided text](https://developer.mozilla.org/en-US/docs/Web/API/Element/innerHTML).

4. **[P1] Initial synchronization and reconnect depend on timing and cached decks.**

   [Host synchronization](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:233>) deletes the deck from every handshake response. The only normal full-deck transfer is a [fixed 500 ms send after opening the board](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:1343>). With storage unavailable and board initialization delayed beyond that send, the host had one category and the board had zero, even after handshake retries.

   Separately, [board retries stop after initial success](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/board-ui.js:58>). Reloading the host loses its direct-window registry. The already-connected board does not re-register, including on focus, because `initialSyncReceived` stays true. With BroadcastChannel disabled, the host selected a clue while the board stayed blank. Opening the board again manually can restore the bridge, but automatic healing is absent.

   **Change:** Use a ready/acknowledge handshake carrying a complete snapshot and deck ID, with bounded initial retries and a low-frequency connection-health check after connection. Re-register after host reload. Transfer immutable deck content once per deck version, then send compact gameplay updates. Show connected/reconnecting/disconnected status. File-URL storage behavior is not a portable guarantee: [MDN documents it as undefined](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

5. **[P1] Reload recovery restores data but not the active gameplay interface.**

   [Host recovery](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:101>) launches the dashboard without reconstructing its clue controller. [Board recovery](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/board-ui.js:46>) redraws the grid without reconstructing the active clue overlay. Chrome confirmed a non-null current clue with hidden controls/overlay after each reload. Wrong-answer lockouts live only in the host-local `disabledBuzzers` array. Answer-reveal state and timer deadlines are not persisted, and starting Final does not set the host's current clue.

   **Change:** Persist an explicit clue stage, selected clue ID, locked-out team IDs, wagering team, answer visibility, and timer deadline. Reconstruct the UI from that state without replaying scoring or audio events. Restore the active controller without calling the existing activation function, which resets wager and lockouts. Make the host the sole authoritative state writer; the board currently writes partial/stale snapshots to the same storage key.

6. **[P1] Daily Double quick scoring can award the wager to another team.**

   After selecting the wagering team, [quick-score generation still loops through every team](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:1072>). Reproduction: Team 1 wagers $100, then Team 2's quick-score plus button awards Team 2 $100 and spends the clue. Ordinary quick-score minus also closes a clue immediately, unlike ordinary Incorrect, which permits remaining teams to answer. It can also bypass a previous wrong-answer team's lockout.

   **Change:** Route all grading through one rules-aware action. Limit Daily Double scoring to its wagering team. For standard incorrect answers, apply the same lockout and continue/close behavior regardless of which control is used. Validate team eligibility and active-clue identity inside the scoring action, not just in the visible buttons.

7. **[P1] Final Jeopardy eligibility changes during judging, and a missing Final clue crashes.**

   [Final participants are recalculated from current scores](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:584>) every redraw. A team starting with $100 and wagering $100 disappears from the judging panel after an incorrect answer brings its score to $0. Its result cannot then be corrected through that panel. Imports without a Final clue still allow progression and wagering; [the judging panel dereferences the missing clue](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:738>), producing a runtime error. A separate header completion button also permits completion before all Final answers are judged.

   **Change:** Freeze Final participants and their starting scores when the round begins. Keep every participant available throughout judging, including after a zero score. Guard round transitions according to deck contents and explicit Final stages; apply the same completion guard to every completion control.

8. **[P2] Synchronization duplicates effects and loses category-introduction state.**

   [The broadcaster sends through both transports](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/app.js:221>), and the board handles both without event deduplication. On localhost, one clue click produced two `SHOW_CLUE` receipts. This repeats sounds and can schedule two delayed wager reveals. Round advancement [sends only the new phase](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:479>), leaving the board's category-introduction index unchanged. The host entered Double introduction index 0 while the board remained null and showed no introduction.

   **Change:** Include session ID, event ID, and monotonic state revision; ignore duplicates and older revisions. Use one chosen transport with fallback, or deduplicate across both. Send the complete phase transition, including introduction stage. Include deck version in redraw decisions. Isolate storage and channels per session so two hosts cannot cross-control separate games. Validate message shape and the expected source window.

9. **[P2] The single-file build changes strings and removes displayed dollar signs.**

   [Script inlining uses a string replacement](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/scratch/build.js:108>). JavaScript replacement-string rules collapse `$$` into `$`, so the template `$${clue.value}` becomes `${clue.value}`. The packaged host displayed `200` where the source app displayed `$200`. This affects multiple currency templates.

   [The regex minifier](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/scratch/build.js:33>) also changes string contents: `'A - B'` becomes `'A-B'`, and a URL containing a later `//` is truncated. Current core-parser parity checks passed, but this is unsafe for further development.

   **Change:** Use replacement callbacks when inserting script text. Use a parser-based build minifier, such as [Terser](https://terser.org/docs/cli-usage/), as a development dependency, preserving zero runtime dependencies. As a simpler safe alternative, inline unchanged source with callbacks and gzip it. That approach measured approximately 38,886 bytes with the current wrapper, only about 9.7 KiB larger than today's package. Verify visible strings and gameplay in both outputs, rather than syntax alone. Use UTF-8 byte lengths for size reporting instead of string `.length`.

10. **[P2] Text encodings and Unicode identity need an explicit import policy.**

    UTF-8 accents, emoji, Japanese characters, and a UTF-8 BOM worked. UTF-16LE with a BOM also worked in tested Chrome. Windows-1252 `Café` became `Caf�`, and the UI still reported success. [FileReader uses its default decoding](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/host-ui.js:301>) with no encoding selection or corruption diagnostic.

    [Category grouping only lowercases](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/app.js:155>). Visually identical `Café` and `Café` using a combining accent became two categories. A zero-width character before `Round` caused a missing-header error. Case-only category variants currently merge; that is a policy choice that should be visible rather than accidental.

    **Change:** Recommend UTF-8 exports, detect BOMs, and provide a selectable legacy encoding when needed. Surface replacement characters and invisible header characters in diagnostics; do not blindly strip all Unicode from clue content. Normalize category comparison keys to NFC while preserving display text. NFC makes canonically equivalent strings comparable, as described in [Unicode normalization guidance](https://www.unicode.org/faq/normalization.html). Decide explicitly whether case differences should merge categories. Add automatic text direction for mixed-language content.

11. **[P2] Long or structured clues can become unreadable despite successful ingest.**

    [Clue layout](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/css/style.css:297>) uses large fixed-size text in a centered full-screen overlay, with no maximum-height scrolling or fitting logic. A long clue extended from -1084 px to 1884 px in an 800 px viewport. Parsed newlines are also visually collapsed by normal CSS whitespace handling, affecting poems, lists, code, and multi-part clues. There are no responsive media queries or reduced-motion rules in the stylesheet.

    **Change:** Add viewport-aware text sizing, wrapping of long tokens, a scrollable fallback, `white-space: pre-wrap` for structured clues, and a preview at representative display sizes. Include the media, wager card, and revealed answer in the height calculation. Preserve a host font-size override, but keep a readability limit.

12. **[P2] Final Jeopardy has music but no visible 30-second countdown.**

    [Final clue display](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/board-ui.js:148>) starts music but does not start the visual countdown. Chrome confirmed the timer remained hidden. [The audio sequence](</Users/evanwhitmer/Documents/AI Projects/Jeopardy Application/src/js/audio.js:205>) schedules seven loops of sixteen quarter-second notes: 28 seconds, then a 0.8-second closing chime. The documented 30-second duration is not actually represented by a shared clock.

    **Change:** Store one deadline for the round, render a numeric/bar countdown on both screens, and schedule audio against the same duration. Provide pause/resume and replay controls, with configurable response times. Cancel delayed callbacks on clue changes or round transitions; existing delayed callbacks should verify the clue/session revision before changing the UI.

**CSV and character coverage**

| Structure | Observed result | Recommendation |
| --- | --- | --- |
| Accents, emoji, Japanese, apostrophes, slashes, hyphens, typographic quotes | Preserved by parsing | Keep Unicode; avoid ASCII-only sanitization |
| Quoted commas, escaped ASCII quotes, quoted multiline fields | Parsed correctly | Retain this behavior |
| UTF-8 BOM | Accepted | Retain regression coverage |
| UTF-16LE BOM | Accepted in tested Chrome | Document tested support; verify other browsers |
| Windows-1252 text | Replacement characters; successful status | Encoding choice and diagnostics |
| Canonically equivalent accented category names | Separate categories | NFC comparison keys |
| Case-only category variants | Merged into one category | Explicit grouping policy |
| HTML tags in names/clues | Interpreted in previews/titles | Literal DOM text assignment |
| Long/multiline displayed clues | Clipping and collapsed formatting | Fitting, scrolling, preserved line breaks |
| Missing values / formatted money / negative values | Accepted, misread, or zero/non-finite | Strict number validation |
| Duplicate values in one category | Shared spent-state key | Stable clue IDs and duplicate diagnostics |
| Unknown round / missing answer | Row silently omitted | Row-specific errors |
| Unclosed quote / unescaped inch quote | Content can be swallowed; empty deck still accepted | Parse errors with line and column |
| Multiple Final clues | Last row silently wins | Reject or make multiple finals an explicit format |
| Zero-width character in header | Missing-column error | Explain and highlight invisible characters |
| Semicolon/tab-separated input | Comma-only parser has no alternate-delimiter path | Offer delimiter choice/detection |
| Unexpected Daily Double flag or media type | Flags other than TRUE become false; unknown media types are not rendered | Validate against the supported schema |

An unescaped ASCII quote in an unquoted field is malformed CSV; the fix is a useful error, not arbitrary guessing. Properly quoted fields should double embedded quotes. [RFC 4180 documents these conventions](https://www.rfc-editor.org/rfc/rfc4180.html). Smart quotes are ordinary content, not CSV delimiters.

**Performance improvements, in order of likely value**

- **Eliminate duplicate message handling and spectator storage writes.** This improves both correctness and unnecessary work. Store immutable deck content separately from small session state. Name/color edits and font-slider input currently save the complete deck and trigger broad spectator work on every input event. Debounce noncritical settings persistence; commit scoring and phase changes immediately. Browser storage operations are synchronous, as described by [MDN's Web Storage documentation](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API).
- **Preload media with a budget.** The board scans all rounds on every sync and starts every new image download/decode immediately. Preload the active round or next few likely clues with bounded concurrency; clear/retry failures appropriately when decks change. Report missing local files and oversized images. Optimize actual media files, which can outweigh the entire app.
- **Reduce persistent rendering hints and broad animations.** Every `.glass` element has `will-change`, blur, and forced transforms, while several selectors use `transition: all`. Limit hints to components that actually animate, transition specific properties, and offer a lower-effects projector mode. These are profiling candidates, not measured frame-rate gains. [MDN advises using will-change sparingly](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/will-change).
- **Update existing nodes when only data changes.** Rebuild scores or the host grid only when needed. Cache image URL lists and use a Set for spent-ID lookups. For the present 60-clue decks, these are secondary to synchronization and media work.
- **Use a transform for the timer bar.** Animate `scaleX` with a fixed origin instead of writing `width` each frame; avoid combining a per-frame width change with a width transition.
- **Keep parsing simple for ordinary decks.** The sample parser is already fast. Add file-size/row-count limits and progress feedback first. Consider chunking or a worker only if measured large-deck imports block interaction. Large CSV support also requires a usable grid layout, not just faster parsing.

**File-size and distribution improvements**

- Fix literal-preservation defects before pursuing extra compression. The 28.3 KiB package is already small; it does not contain downloaded fonts or clue media.
- Move repeated inline visual styles into reusable CSS classes. Host UI text/style templates account for the largest source file; this also makes responsive and accessible styling easier.
- Generate the unified and split HTML entry points from a shared template. `host.html` lacks the newer settings panel and inline Daily Double error element, while `index.html` contains them. The duplicated markup is already drifting.
- Prefer a system font stack for the smallest fully local release. If custom fonts are essential, bundle a limited set of local WOFF2 files with the needed language coverage. The current CSS starts with a remote Google Fonts import, so typography is not fully bundled.
- For served delivery, let HTTP compression avoid Base64 overhead and load the active view's code. For direct-file delivery, retain the self-contained package and feature-check decompression support. Base64 adds 6,820 bytes to the current gzip payload; a self-extracting file also incurs startup decompression and parses both view scripts in each window.
- Exclude tracked `.DS_Store` files and development documents from release packaging. Keep the repository documents for maintainability; they are not runtime payload.

| First | Connection status and an explicit reconnect control | Hosts can diagnose a frozen spectator display |
| First | Undo/redo backed by a scoring-event log | Correct an accidental grade without guessing prior scores |
| First | Export/import a complete session backup | Recovery independent of browser storage and browser/device changes |
| Next | Explicit rules and round-format settings | Single-round games, optional Final, custom values, timers, penalties, and Daily Double counts |

| Next | Offline media picker/package and preflight validation | Relative URLs currently resolve against the application, not the uploaded CSV's folder |

| Next | Answer aliases, host notes, sources, media descriptions, language metadata | More nuanced judging and more useful educational decks |

| Later | Audio/video clues with explicit controls and failure feedback | Broader clue formats once images and offline assets are reliable |

The architecture can remain vanilla JavaScript and local-first. A useful internal boundary is an immutable validated deck, one authoritative gameplay state, one scoring/transition function, and views that render that state.

**Recommended implementation sequence**

1. Add import diagnostics, strict values, stable IDs, and literal text rendering.
2. Unify scoring rules and freeze Final participants; guard absent rounds and incomplete Final results.
3. Implement complete handshake snapshots, event deduplication, reconnect, and persisted clue stages.
4. Fix build substitution/minification and establish source-versus-package behavior checks.
5. Add readable structured-clue layouts and a shared configurable timer.
6. Profile media-heavy decks and projector hardware before further performance work; then add undo, backups, and deck editing.

Release verification should cover source and packaged variants, localhost and direct-file launch, host/board reload during normal and Daily Double clues, storage-unavailable fallback, Unicode/quoted/multiline CSV fixtures, duplicate clues, wrong-answer lockouts, Final score corrections at $0, and offline media failures.
